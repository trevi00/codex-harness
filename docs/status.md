# 0.1 구현 범위

## 실행·검증된 부분

- 독립 프로젝트, uv lock, Dockerfile 및 메모리 제한이 있는 Compose.
- 육하원칙 JSON Schema, 조직 그래프의 3계층 검사와 기본 메시지 라우팅 권한.
- PostgreSQL 원자적 사건 집계, 메시지/사건 중복 제거, outbox, 훅과 체크포인트 영속화.
- Redis Streams 발행·ACK·미확인 회수·dead-letter 어댑터.
- 독립 두 번째 사건에서 훅 작업 생성. 선언형 명령 교정 훅 및 실제 명령 실행 연결.
- 후보→팀장 검수→지휘자 검수→카나리아→활성화/거부→롤백 상태 전이.
- 정확한 후보 revision/spec hash 검사, 이전 checkpoint generation의 쓰기 거부.
- 결정론적 컨텍스트 편성·예산·필수 계약 검사·출처·제외 이유.
- Tree-sitter Python 코드/주석 관계 색인, 그래프 확장 조회, pgvector 어댑터.
- Codex CLI 시작 및 호스트에서 실제 파일 읽기·쓰기·JSON 출력 검증.

## 초기 기능의 한계

- `demo`는 자동화된 고정 fixture다. LLM이 독립 PR 검수한 결과가 아니다.
- 로컬 프로세스의 actor ID를 신뢰한다. 메시지 서명·생산자별 Redis ACL은 아직 없다.
- 상태 저장은 JSONB 문서 테이블과 전역 트랜잭션 잠금으로 시작한다. 규모가 커지면 집계별 잠금과 전문 테이블로 이행한다.
- checkpoint generation은 checkpoint 쓰기를 막는다. 모든 도구 부작용에 대한 분산 lease/fencing은 아직 없다.
- supervisor는 지정 소비자의 기동과 유휴 종료를 연결한다. Codex 작업의 70% 측정·도구 종료 대기·실제 세션 교체는 아직 연결하지 않았다.
- 임베딩은 주입 가능한 어댑터만 제공한다. 테스트 벡터는 의미 임베딩으로 표시하지 않는다.
- 함수 노드 ID에는 위치가 포함되며 코드 이동 시 달라진다. 장기적 심볼 계보/rename 추적은 미구현이다.
- hook rollback은 새 훅을 비활성화해 기본 명령으로 돌아간다. 컨테이너 버전·DB 마이그레이션 복구와는 다르다.
- 메시지의 시간/선행 조건 메타데이터를 스키마로 검증하나 일반 작업 스케줄러의 실행 조건으로는 아직 적용하지 않는다.

1. 태스크 계약·출처·조직 권한을 가진 실제 Codex 작업 디스패치와 독립 검수 결과 수집.
2. 실제 사용량 스트림 기반 70% 인계와 실행 소유권·재시작 복원.
3. Git 작업트리·커밋·PR·검수 증거를 연결하는 포트, 실제 배포 카나리아·known-good 복구.
4. 임베딩 모델, 변경분 색인, 운영 사건/조직/작업과 코드 그래프의 통합 조회.
5. GitHub Trending·GeekNews 리서처와 근거 검증·중복 후보 제거.
6. 버전 고정 평가 기준, RLM 외부 자료 처리, 정책/컨텍스트 편성기 자체의 자기 개선.
